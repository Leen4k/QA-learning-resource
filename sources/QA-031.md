# QA-031 — Running Postman collections from the CLI with Newman

> Dossier, not lesson content. Every claim below must be re-read at source
> before it ships in a lesson.

- **Verdict:** WRONG-DOCUMENT
- **Named source:** https://learning.postman.com/docs/getting-started/quick-start/
- **Best primary source:** Postman Docs — Newman CLI reference — https://learning.postman.com/docs/reference/newman-cli/command-line-integration-with-newman
- **Exact sections to read:** "Install and run Newman" (→ Install Newman; Run a collection with Newman; Run a collection with an environment; Example collection run with failing tests); "Newman reporters" (built-in reporter list; `-r`/`--reporters`; export flags); "Newman command reference" (§Output options, §Exit status, §Data file example)
- **Read time:** ~25 min

## a. Does the named source cover this?

No. The quick-start page does not mention Newman anywhere. Its five headings are
"Postman quick start", "Send an API request", "How it works", "Create a
collection and save your request", "Write a test for your API request" — all
GUI work in the desktop app. There is no npm install, no `newman run`, no
reporter, no command line of any kind.

It is a genuine **prerequisite** — the learner needs a collection with a test in
it before there is anything to run headless — but it contributes zero to the
deliverable. A learner who reads only this page cannot produce a Newman report.

**Also broken:** the plan-era doc path `/docs/collections/using-newman-cli/...`
now 404s. Newman docs live under `/docs/reference/newman-cli/`. Any lesson link
using the old path will dead-end. (Appending `.md` to these URLs serves clean
raw markdown — useful for verification.)

## b. Best primary source

Postman's own Newman section, `/docs/reference/newman-cli/`. Three pages carry
the whole deliverable:

1. **Install and run Newman** — `.../installing-running-newman` — prerequisites
   (Node v16+), `npm install -g newman`, running from a file, from a URL, and
   with an environment.
2. **Newman reporters** — `.../newman-built-in-reporters` — the five built-in
   reporters and the `-r` / `--reporter-*-export` flags.
3. **Newman command reference** — `.../newman-options` — `-e`, `-d`, `-n`,
   `--bail`, `-k`, `--suppress-exit-code`, `--verbose`, plus §Exit status.

Secondary but authoritative for option-level detail: the Newman README at
https://github.com/postmanlabs/newman (same flags, plus the programmatic
Node.js API).

## c. What it leaves out

- **The deliverable's "readable report" does not exist in the built-ins.** The
  five reporters are cli, json, junit, progress, emojitrain. JSON and JUnit XML
  are machine formats; nobody reads them. The docs punt: "you can use an
  external reporter or build a custom reporter." The de-facto answer is the
  third-party `newman-reporter-htmlextra` — not Postman's, not linked from the
  reporters page. The lesson must supply this bridge or the deliverable stalls.
- **Exporting the collection and environment to JSON** is assumed, not taught.
  The docs start from "you have a `my-collection.json`".
- **CI exit-code behaviour.** The CI page (`.../continuous-integration`) shows
  only two `newman run` URL commands and says nothing about exit codes or
  failing a build. §Exit status in the command reference is the place to look —
  read it, I did not.
- **OAuth 2.0 is unsupported** ("Newman doesn't support OAuth 2.0
  authentication"), so a learner pointing Newman at an OAuth-protected API hits
  a wall the GUI never showed them.
- **The v3-format trap** — see (d). Not mentioned on the quick-start page the
  learner comes from, and it can make the whole exercise fail at step one.

## d. Credible disagreement

**Postman disagrees with the task's tool choice.** Its own Newman landing page
opens with a compatibility warning and steers readers to the Postman CLI
(`postman collection run`), with a closing section "Migrate from Newman to the
Postman CLI". Release cadence corroborates maintenance mode: Newman 6.2.1
(2024-08-20) → 6.2.2 (2026-01-16), and 6.2.2 was dependency updates only.

This is not a reason to drop the task — Newman is still the tool most CI
examples, tutorials and existing pipelines use, and the concepts transfer
directly. But the lesson should say plainly which era it is teaching, and
should have the learner export a **v2.1** collection to avoid the trap.

**RST disagrees with what the green report means.** Bach & Bolton, "Testing and
Checking Refined" (2024-08-10), separate the two: checking is "the mechanistic
process of verifying propositions about the product", whereas testing is the
human process of "experiencing, exploring, and experimenting". A Newman run
produces checks. A wall of green ticks in an HTML report is evidence that
propositions someone already thought of still hold — not evidence the API is
good. Worth one paragraph so the artifact is not oversold.

## e. Worked examples worth adapting

- **`newman run examples/sample-collection.json`** — the README's own sample
  collection, ships in the repo. Zero-setup first run.
- **"Example collection run with failing tests"** — a named section on the
  install-and-run page. The failing run is the more instructive artifact: it is
  what makes the report worth reading and what drives the CI exit code.
- **`--reporter-htmlextra-showOnlyFails`** — good exercise shape: break one
  assertion deliberately, regenerate, show only the failure.
- **Data-driven run** — `-d` (JSON or CSV) with `-n` iterations; the command
  reference has a §Data file example. Turns one request into a small suite.
- **Collection-by-URL against the Postman API** — from the CI page; shows the
  real CI pattern (no checked-in JSON) but needs an API key, so treat as an
  extension, not the main path.

## Verbatim quotes

Postman Docs, Newman CLI landing page:
> "Newman is a command-line tool for running Postman Collections. Use Newman to
> run and test collections from the command line instead of in the Postman app."

Same page, compatibility notice:
> "Newman isn't compatible with the collection v3 format used in Postman v12 and
> later, which is the only collection format supported in Native Git workflows."

Install and run Newman:
> "Before installing Newman, make sure you've installed Node.js v16 or later."
> `npm install -g newman`
> `newman run my-collection.json -e dev-environment.json`
> "Newman doesn't support OAuth 2.0 authentication."

Newman reporters:
> "CLI, JSON, JUnit, Progress, Emoji train"
> "The CLI reporter (cli) is turned on by default when using Newman in the terminal."
> `newman run my-collection.json -r cli,json`
> "--reporter-json-export" / "--reporter-junit-export"
> "you can use an external reporter or build a custom reporter"

Newman command reference, `-r`:
> "Generate a report about the current collection run. Specify one or more
> reporter names: `cli` (default when using Newman as a CLI), `json`, `junit`,
> `progress`, and `emojitrain`."

newman-reporter-htmlextra README (github.com/DannyDainton/newman-reporter-htmlextra):
> `npm install -g newman-reporter-htmlextra`
> `newman run collection.json -r htmlextra --reporter-htmlextra-export ./results/report.html`
> Defaults to the `./newman/` folder. Requires Newman v4.2.3+.

Bach & Bolton, "Testing and Checking Refined" (https://www.satisfice.com/blog/archives/856):
> "checking [is] the mechanistic process of verifying propositions about the product."
> "Testing can only be *supported* by tools... whereas checking is a process that
> can, in principle be performed by a tool instead of a human."
